## 一、项目背景与询价目的

我们正在研发一套面向自主智能体（AI Agent）的密码身份中间件，采用「标识—凭证—委托—存证」四层架构，底层使用国密算法体系（SM2/SM3/SM4/SM9）。v3.0 需要将标识私钥从软件实现迁移至国密硬件承载，并解决凭证签发吞吐瓶颈。

现就**支持 SM9 的密码运算硬件**向贵司询价，并寻求 POC（概念验证）合作。

### 1.1 我们的技术特征（影响选型的关键点）

1. **以 SM9 无证书标识为核心差异化**：标识层使用 SM9（GB/T 38635 / GM/T 0044-2016）实现无证书身份标识，取消 X.509 证书链。**硬件必须原生支持 SM9 签名/验签/密钥对生成，而非仅支持 SM2。**
2. **委托链逐跳验签**：一次业务请求可能触发 1–10 跳委托链验证，每跳含 SM2 或 SM2+ML-DSA-65 混合验签。
3. **高并发签发**：目标签发吞吐 5,000 TPS（每秒 5,000 次凭证签发，每次含 1 次 SM2 签名 + 1 次 SM3 杂凑）。
4. **失败关闭（fail-closed）**：任何密码运算异常必须能被中间件捕获并拒绝服务，不得静默降级。
5. **部署形态**：中间件为 Python 3.13 服务端应用，运行于 x86_64 Linux 服务器（信创环境适配为加分项）。

## 二、功能需求

### 2.1 必需要求（Must）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-01 | SM9 数字签名与验签 | 提供可调用接口，支持 GM/T 0044-2016 规定的签名/验签算法 |
| F-02 | SM9 密钥对生成 | 支持主密钥与用户标识私钥的产生，私钥不以任何形式导出硬件边界 |
| F-03 | SM2 数字签名与验签 | 支持 GM/T 0003 规定的签名/验签 |
| F-04 | SM3 密码杂凑 | 支持 GM/T 0004，含 HMAC-MAC |
| F-05 | SM4 分组密码 | 支持 ECB/CBC 等模式（用于凭证载荷加密） |
| F-06 | 硬件真随机数 | 物理噪声源产生，符合 GM/T 0005 |
| F-07 | 密钥生命周期管理 | 生成、存储、导入、导出、备份、恢复、销毁 |
| F-08 | 三级密钥保护体系 | 密钥分级存储与访问控制 |
| F-09 | 标准软件接口 | 至少提供 SDF（GM/T 0018-2012）或 PKCS#11；提供 Python 调用方式或 C 动态库 + Python 绑定示例 |
| F-10 | 多进程/多线程并发调用 | 同一设备支持多服务进程并发调用，不互相阻塞 |
| F-11 | 失败可观测 | 运算失败返回明确错误码，不允许无返回或静默成功 |
| F-12 | 国密算法协商标识 | 支持在签名中携带算法档位标识，供验签侧识别（用于防降级） |

### 2.2 加分要求（Nice to have）

| 编号 | 需求 |
|---|---|
| N-01 | 支持 SR-IOV 硬件虚拟化，供多虚拟机/容器共享 |
| N-02 | 支持多卡级联扩展 |
| N-03 | 适配国产 OS（麒麟、统信、中科方德）与国产 CPU（飞腾、龙芯、海光、鲲鹏、兆芯） |
| N-04 | 支持 ML-DSA / SLH-DSA 等后量子签名算法（我们有抗量子迁移需求） |
| N-05 | 提供国密 SSL VPN / IPSec 硬件加速（非必需） |
| N-06 | 支持跨域公共参数交换（对应我们 FR4-06 跨域撤销传播需求） |

## 三、性能需求

### 3.1 硬性指标

| 编号 | 指标 | 要求 |
|---|---|---|
| P-01 | SM2 签名有效吞吐 | **≥ 5,000 次/秒**（经标准接口调用的端到端有效值，非卡内纯算法值） |
| P-02 | SM2 验签吞吐 | ≥ 10,000 次/秒 |
| P-03 | SM9 签名有效吞吐 | ≥ 2,000 次/秒（说明：SM9 运算量高于 SM2，此指标可议） |
| P-04 | SM9 验签吞吐 | ≥ 5,000 次/秒 |
| P-05 | SM3 杂凑吞吐 | ≥ 1 Gbps |
| P-06 | 并发调用延迟 P99 | ≤ 20 ms（16 并发下） |

> **关于 P-01 的特别说明**：我们清楚标称值（如 45 万次/秒）是卡内纯算法吞吐。经 SDF/PKCS#11 接口调用后通常有数量级折损。**我们要求的是端到端有效吞吐，并会以 POC 实测为准。** 请按此口径报价与应答。

### 3.2 可扩展性要求

单设备不能满足 P-01 时，请说明多卡并行或多机集群的扩展方案与线性度。

## 附录 A：术语对照

| 术语 | 说明 |
|---|---|
| SM9 | GM/T 0044-2016 标识密码算法，基于椭圆曲线双线性对，以用户标识直接作公钥，免证书 |
| SDF | GM/T 0018-2012 密码设备应用接口规范 |
| DPA | 差分功耗分析（Differential Power Analysis），侧信道攻击的一种 |
| fail-closed | 失败关闭：异常时拒绝服务而非降级放行 |
| 委托链 | 智能体间逐级授权形成的凭证链，本项目中深度可达 10 跳 |

## 附录 B：我们的四层架构与硬件的对应关系

| 层 | 功能 | 硬件承载需求 |
|---|---|---|
| Layer 1 标识 | SM9 无证书身份标识 | SM9 密钥对生成、标识私钥生成与存储（**F-01/F-02**） |
| Layer 2 凭证 | SM2 / SM2+ML-DSA 混合凭证签发 | SM2 签名、SM3 杂凑（**F-03/F-04**） |
| Layer 3 委托 | 委托链逐跳验签、scope 收敛 | SM2 验签（**P-02**）、并发调用（**F-10**） |
| Layer 4 存证 | 撤销累加器、哈希链锚定 | SM3 杂凑、SM4 加密（**F-05**） |
